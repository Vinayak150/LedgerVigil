# Native approval authoring UI

This frontend slice uses the existing 0019 approval API without changing backend code, database schema, permissions or accepted financial rules. The server's `allowed_actions: APPROVE` is required for a new action; no local role assumption grants approval. The form additionally verifies native SANDBOX scope, exact ETag, revision/ledger/proposal/run identity, supported completed simulator profile and immutable input/result hashes. Maker/editor exclusions are defensive presentation checks; the API remains authoritative for all independence, cooling-off and freshness gates.

The comment is optional and stored exactly as entered, with a 4000-code-point limit and no malformed UTF-8/NUL. Empty comment is omitted from the request rather than inventing a required reason. A separate acknowledgement confirms review of the exact current saved revision and pinned simulation and explains that approval is a workflow decision, not execution or accounting sign-off. “Inspect current pinned result” resets the simulation view to the current run and focuses its result heading, including after historical browsing.

Before POST, tab storage persists the original comment, revision, simulation ID, input/result hashes, If-Match, UUID key and start time. Scope includes verified tenant, actor, proposal and ledger. No session credential is stored. A corrupt saved record blocks new requests; unavailable storage prevents sending until recovery metadata can be saved. Unconfirmed requests lock their original body and can be restored even when the new head no longer advertises APPROVE.

There is no automatic POST, automatic key replacement or optimistic proposal-state update. Network/5xx, unexpected or mismatched success, in-progress, idempotency-key conflicts and authentication/permission failures preserve the original request. A read of current head/history is explicitly a separate observation; it does not settle a request still running. Only an exact revision/run/version approval receipt confirms the action. Same-key retry stays within 23 hours and refuses clock rollback; later attempts require operator reconciliation. Closing the tab/browser can lose tab-scoped recovery data.

Known typed refusals resolve that request while retaining the draft comment and blocking a new attempt at the displayed version. ALREADY_DECIDED directs the reviewer to history. A dependency-stale response explains the server's atomic STALE transition and reservation release; no approval is claimed. FULL_CAPTURE_CHANGED cannot be bypassed. A 412 requires refresh and inspection of the new current content. Session/segregation refusals retain the original request even if it might have been the first call; an unconfirmed earlier commit is never assumed absent. If a grant wait exceeds the safe retry window, operator reconciliation is required rather than silently issuing a new key.

Confirmed receipts remain visible if a later current-state read or recovery cleanup fails. Closing the receipt refreshes current head and immutable history. Original simulation/verdicts, synthetic provenance and accounting UNREVIEWED status stay unchanged. No execution, rejection, provider access or architectural approval is added. Earlier proposed AP/OV/ADR decisions retain their statuses.
