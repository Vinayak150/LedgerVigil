# RG-02, slice 1: native proof access and release audit

The full execution integrity JSON includes ledger history. This slice applies the accepted Stage 2B permission `evidence.export` to its existing download route. A plain `read` grant or an administrator's `audit.read` no longer authorizes this download. Controller and automation developer permissions retain their accepted mapping. A failed authorization is checked before any conditional304 response or export bytes.

Generation uses the existing verified offline format and bounded read-only generator. It finishes its read transaction, then a second transaction re-verifies the current session, tenant, execution and export permission. The new owner-owned, search-path-pinned function locks identity rows before the session row, rechecks authorization and writes `NATIVE_PROOF_EXPORT_AUTHORIZED` to the existing immutable chained audit. It records a unique export id, actor, session, request, execution, `content_hash` (SHA256), byte length, format and planned response status. Audit metadata uses only string values/compatible keys for the existing canonicalizer. The event authorizes release; it does not claim the client received or saved the bytes.

The response is constructed only after commit. A missing or failed audit yields an error and no proof bytes or proof headers. Each200 and each304 gets its own event and `X-Export-Authorization` id. This intentionally means GET is no longer wholly read-only: proof generation remains read-only, while authorization/audit is a narrowly scoped write. There are no financial writes. Unavailable and foreign execution ids remain indistinguishable for export-authorized users. Body bytes, hashes and the offline verifier remain compatible.

Migration0024 follows the independently reviewed RG-05 candidate0023. It adds one authenticated function and no tables. Earlier migrations, role grants, authentication module, financial posting functions and UI components are unchanged. An empty-history downgrade works; any export authorization event blocks downgrade using full-table constraint validation under FORCE RLS. No audit is removed.

## What remains for RG-02

This is a bounded security slice, not full Family14 completion. Generation is still synchronous; durable jobs/outbox, bounded worker claims/recovery and 15-minute signed download URLs are not implemented. The existing UI still offers its generic download control; users without export permission receive403. Updating the control to reflect session permissions belongs with the async export UI. This package does not create sealed/chained/externally anchored proof packs (RG-04), remove the2000-history bound (RG-07), or authorize external sharing. The formal integrity-artifact versus Family14 classification remains recorded as an open decision; this interim route uses the stricter export permission and audit protection requested for RG-02. No ADR status is changed.

RG-05's independent verdict is VERIFIED with no blocker. Its inherited operator-revocation deadlock and minor422/error-description/no-op-edit findings remain recorded in the Claude review; this slice does not claim to fix all existing writers. The new authorizer specifically avoids session-before-identity locking, and a held operator membership revocation is tested to win with401 rather than500. Q-16 remains open. Accounting stays UNREVIEWED; all proposed decisions retain status, and production/BOOKS/provider gates remain.
