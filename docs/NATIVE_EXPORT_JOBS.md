# Durable native integrity exports (RG-02 continuation)

This extends the independently reviewed native permission/audit slice. Native JSON artifacts remain unsigned internal-consistency evidence with accounting UNREVIEWED. These native JSON routes remain diagnostic exports. Migration 0026 adds Family14 native sealed packs with JSON plus HTML; see PROOF_PACKS.md. Existing proposed decisions retain their status.

## Workflow and authorization

1. `POST /api/v1/executions/{execution_id}/exports` with `Idempotency-Key` and exactly `{"format":"JSON"}` returns202 and a durable job id/Location. A transaction creates the job and its audit. Concurrent retries with the same user/tenant/key resolve to the same job; reusing the key for another accessible execution is refused.
2. `GET /api/v1/execution-proof-exports/{id}` returns metadata only, restricted to the requesting exporter. Read/audit.read alone is insufficient. Other users' and tenants' jobs are masked as missing.
3. The scheduler relays identifiers to Celery. PostgreSQL remains the authoritative queue/outbox: publish happens before dispatch marking, unclaimed delivery is re-published after30 seconds, expired claims are recovered, and fenced completion rejects stale workers. Claims last60 seconds, with at most3 attempts. Retryable failures back off2/4/8 seconds; exhausted/terminal/revoked work becomes DEAD or DENIED and is audited.
4. The restricted `lv_worker` obtains a bounded REPEATABLE READ, READ ONLY snapshot through an owner-owned, search-path-pinned function. It receives only the claimed job's proof facts; no new direct SELECT grant is given on financial or identity tables. The existing independent verifier checks the generated bytes before storage. Input caps, the existing2000-commit bound and16MiB output cap remain enforced.
5. Completion atomically stores the immutable bytes and their SHA256, calculated by PostgreSQL, and appends the build audit. Database constraints check the digest, size, scope and required audit. Completed/terminal job records cannot be edited or deleted through normal SQL. This binds G1's metadata to stored bytes on the new job path; the database is not an independent accounting/financial-proof verifier. It still trusts the reviewed generator/worker and existing API/session boundary.
6. `POST /api/v1/execution-proof-exports/{id}/download-link` issues a15-minute signed relative URL. It binds job, tenant, user, a domain-separated keyed HMAC of the current session hash and expiry. HMAC uses the existing cursor key with a distinct export-link domain prefix. Set the existing persistent LV_CURSOR_KEY for stable multi-process/restart behavior; a random startup key safely invalidates old links on restart. Rotating the key/session or revoking permission can invalidate a link earlier than15 minutes.
7. Download rechecks signature, expiry, current session/permission/ownership and the stored digest, then commits its audit before returning the stored bytes. Tokens are never stored in audit or browser storage. Signed links are session-bound rather than public bearer URLs. Use access logging that excludes query strings; the verification servers disable access logs and packaged traces redact tokens.

The UI now requests a job, polls with bounded abortable waits, requests a fresh link and verifies bytes/scope/manifest before saving. It reuses the same request key for pending work, offers a fresh attempt after terminal failure, and aborts on unmount/tenant target change. Download links are not persisted. Small card headings now use the existing darker heading color to meet contrast requirements in the reviewed view.

## Local operation

Existing `tools.run_maintenance worker` now listens on maintenance and native-exports. `LV_EXPORT_QUEUE` can override the export queue. The existing scheduler and `once` launcher relay both kinds. `--exports-only` permits a dedicated export worker; `--database` accepts only the existing guarded local development/test database names. No credential is printed. The actual HTTP/Celery rehearsal uses a throwaway database and a unique export queue so it cannot consume development maintenance messages.

The durable export row contains dispatch metadata, lease, attempts, terminal state and artifact. This is a combined native queue/outbox record, separate from the older STALENESS_SCAN-only work_item schema. The current `status` CLI still reports staleness health; export state is available per job and terminal failures in audit. Global export dashboards, user cancellation, archival/retention policy and storage capacity controls remain future operational work. Stored artifacts are retained;15 minutes is the link lifetime, not artifact retention.

Migration0025 adds one FORCE-RLS table and restricted functions, preserving existing migrations and financial posting authority. A validated CHECK refuses downgrade whenever any job history exists, including queued jobs. Empty down/up is supported only on disposable databases. A catalog test found PostgreSQL18 flattened an equivalent AND expression during restore; the new size/hash CHECK is now written in that same flattened form. The recovery comparison itself is unchanged.

## Remaining scope

The subsequent 0026 candidate retires the synchronous compatibility route with 410 for authorized exporters, removes its app database execute grant, and treats financial proof downloads as audited exports. The UI requests sealed, independently anchored JSON+HTML proof packs. See PROOF_PACKS.md for the complete current candidate behavior, operational setup and bounded recovery evidence. Native JSON diagnostics retain their own worker/content trust boundary. No provider access, AI, accounting approval or production readiness is implied.
