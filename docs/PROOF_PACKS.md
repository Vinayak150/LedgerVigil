# Native proof packs, exports and independent recovery anchors

Candidate migration 0026_proof_packs; native SANDBOX only. This implementation completes the native code paths for RG-02 and RG-04. Independent review and integration are separate from implementation. Installed source remains the 306-file 0022 tree until integration. No accounting, provider, production or offsite-readiness approval is implied. D-1–D-11, PA-011-1, other proposed decisions, Q-16 and accounting UNREVIEWED retain their statuses.

## Contract and classification

Stage 2B Family 14 and Workflow 6 own proof-pack creation, immutable manifests, export permission, durable jobs and JSON plus readable HTML. ADR-018 permits canonical JSON, a per-tenant SHA-256 chain and independent publication in Git. This candidate uses that Git reference option on the local filesystem; it creates no external account or paid service. The owning accepted architecture/ADR files are unchanged.

Native execution integrity downloads contain organization financial history and are treated as evidence exports. All full artifact downloads require evidence.export, a durable stored artifact and a committed audit record. GET /api/v1/executions/{id}/proof is retired: authenticated exporters receive 410, read-only callers 403, anonymous callers 401. Its old database authorizer is no longer executable by lv_app. The trusted internal JSON generator remains for compatibility checks and recovery. The earlier durable JSON diagnostic export remains available through its already authorized/audited jobs; it makes no sealed-pack claim.

Read permits requesting a proof pack and reading its status, verification result and manifest metadata. Full content is released through the authorized export only. GET /manifest deliberately returns hashes, chain and proposal/ledger metadata, not the entire financial manifest. BUNDLE is the native export format for a ZIP containing canonical manifest.json and escaped report.html; JSON and HTML are supplied together. These are explicit API refinements, documented in generated OpenAPI, not silent amendments to accepted decisions. Historical revision requests remain refused if that revision is not current; historical packs already built remain addressable by pack id. AI content is null because AI is not implemented.

## Data and state

The private proof_pack, proof_pack_chain and proof_pack_request tables use FORCE RLS; app/worker/seed/ingest logins have no direct access. Privileged functions use fixed search paths; worker inventory policies are restricted to session_user lv_worker. The app can call pack_status, audited pack_request and audited pack_export_request, not the internal CREATE helper.

BLOCKED, REJECTED, EXECUTED and NEEDS_ATTENTION transitions atomically enqueue a captured revision/version/simulation. The worker builds only frozen revision/simulation facts and decisions whose resulting_version is at most the captured version. Display names, email addresses, live proposal state, general comments, export URLs and export/seal timestamps are excluded from content. Decision timestamps remain committed evidence inside content. Decision reason/comment text is represented by its SHA-256 commitment. A later decision/execution produces a new pack, linked with previous_pack_hash. Creation/sealing/export changes no financial record or counter.

The native completion outbox remains immutable. Its payload and id are read into the execution pack, and PROOF_PACK_ANCHORED records notification_id as its consumption receipt. The scheduler also finds predecessor native completion notifications with no pack and queues them idempotently. It does not mutate the old notification's historical PENDING field or claim to deliver external notifications.

Internally: DRAFTING -> SEALED -> ANCHORED. Public metadata exposes ANCHORED as SEALED plus its Git commit and exported timestamp. Three claims, 60-second leases, fences and publication retries protect each job. Third-claim process loss becomes DEAD or ANCHOR_FAILED when revisited after expiry. Such a failure blocks the tenant's later packs rather than permitting a chain fork; an operator must diagnose it. Missing anchor configuration leaves work pending and never invents an anchor. These are local operating defaults, not production SLOs.

## Integrity and trusted boundary

manifest_schema is lv-proofpack/1. The restricted RFC 8785 profile forbids floating-point JSON numbers, unsafe integers and broken Unicode; amounts and large financial sequences stay exact strings. UTF-16 property ordering is cross-checked against ECMAScript. No Unicode normalization is applied. See https://www.rfc-editor.org/info/rfc8785/.

content_hash = sha256: + SHA256(JCS(content)). The previous head starts as sha256: followed by 64 zeroes. chain_hash = sha256: + SHA256(UTF8(content_hash || previous_chain_head)); the two fixed-length prefixed hashes are concatenated without a separator. This explicit encoding is versioned as lv-proofpack/1. sealed_at is outside content hashing. The database binds supplied content to the captured source JSON, calculates its hashes and atomically writes the tenant head and seal audit. The worker performs JCS; it remains trusted for serialization and rendering.

The worker builds a deterministic ZIP, commits its content/chain/bundle hash plus financial checkpoint in a separate SHA-256 Git repository, then acknowledges the exact bundle and Git commit in PostgreSQL. If the Git commit succeeds and the database acknowledgement fails, a retry finds the identical committed anchor and completes without another commit. Late fenced workers cannot acknowledge or mark another worker's claim failed. An audit omission prevents a successful request/seal/anchor/download acknowledgement.

Git's committed objects, not editable worktree files, are the authority. Download verifies the exact stored bundle against its historical committed anchor and verifies the tenant prefix against the latest independent head before final authorization/audit. The database computes the export digest and only accepts an already anchored pack's identical bytes. Link scope uses a domain-separated keyed HMAC of the session hash, so the signed token no longer exposes a value usable as a database session credential (Claude X1). Other Q-16 trusted API/worker assumptions remain.

A Git commit here is not a digital signature, independent accountant review, or an offsite service. A privileged OS operator who can replace both stores can defeat local independence. A bundled copy of test anchors is reproduction evidence, not a separately trusted public timestamp.

## Recovery and limits

The existing verify_recovery drill now checks restored data against LV_ANCHOR_REPOSITORY when configured; absent configuration reports NOT_CONFIGURED. It still verifies schema/security, table fingerprints, financial replay, counter/balance agreement and scoped database ACLs. The anchor check compares database tenants and all recorded anchored pack ids, chain sequence/hash, bundle hash and exact commit id against committed repository history, then verifies every repository head against the database prefix and financial checkpoints. Missing tenants and stale repository copies are refused, as is a database older than its independent head. Readers use committed Git objects without creating lock files, including on a read-only mirror.

The native rehearsal uses real pg_dump/pg_restore: a current backup passes all checks; a backup taken before execution restores consistently and passes ledger replay, yet fails the separate latest Git head. This demonstrates detection of lost anchored history. It does not detect an unanchored tail, establish RPO/RTO, fresh-machine restore or prove offsite durability. Unanchored tail and offsite restore remain NOT_ATTESTED. The earlier RG-05 F1 lock-order finding, Q-16 and unrelated RG-03/RG-06/RG-07/RG-08 are not closed by this implementation.

Populated downgrade is refused atomically across tenants. An empty 0026 downgrade restores 0025 helpers and grants; subsequent upgrade can discover and enqueue a genuine predecessor native execution notification. No existing migration is rewritten.
