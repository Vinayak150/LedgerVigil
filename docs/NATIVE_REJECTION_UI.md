# Rejection authoring frontend

Frontend-only slice on the owning 0020 native rejection API. A new rejection requires the server's REJECT hint plus the verified exact current proposal/revision/ETag/pinned native simulation and hashes. The reviewer enters an exact required nonblank reason (4000 Unicode code points maximum) and explicitly acknowledges terminal rejection and release of this proposal's reservations. Original financial records, simulations, verdicts, evidence provenance and accounting UNREVIEWED status are unchanged.

Rejection recovery has its own `lv.rejection.1` namespace and explicit `decision: REJECT` record. It is scoped to verified tenant, actor, proposal and ledger. No session credential is persisted. An approval recovery record cannot be parsed as a rejection. The body, key, revision, ETag, run and input/result hashes are frozen before POST and survive tab reload/session refresh even after the head stops advertising REJECT. There is no optimistic state update, automatic POST or replacement key.

Approval and rejection panels are separate. In-memory busy/pending/confirmed/corrupt/storage/error-version locks disable new opposite decisions; immediately before sending a new request the component also reads the peer recovery record synchronously, so a pending or corrupt peer cannot be missed during initial mount. Typed draft text stays separate. An original pending request can still be explicitly retried with its own identity. If both earlier requests exist, neither is converted into the other; the server's shared decision constraint remains authoritative and only matching original receipts settle them. A confirmed receipt keeps the opposite panel blocked until current head is refreshed.

A current-state/history read is separate from the original receipt. Only exact revision/run/version REJECTED response confirms rejection. A 5xx, network loss, unexpected success, permission refusal, in-progress response or key conflict keeps the original request. A known typed refusal retains the reason and blocks the displayed version; stale and competing responses claim no rejection. Safe retry is less than 23 hours and refuses backward clock; expiry or corrupt recovery requires operator reconciliation. Tab closure can lose tab-scoped recovery data. No durable operator interface is added.

The existing approval helper now delegates exact target/receipt checks to a shared pure module, retaining its original API and optional comment semantics. Rejection validates the owning Python/PostgreSQL Unicode whitespace set; it does not silently trim or normalize a reason. Explicit .ts imports and the no-emit TypeScript extension option allow these pure helpers to run in the existing native Node test runner.

There is no backend/migration/permission/accepted-contract change. All prior AP/OV/RJ/ADR proposals retain their statuses. Execution, provider writes, accounting approval and proof-pack publication are not added. This slice uses existing layout tokens, labelled controls, focused status/current-result inspection and literal text rendering.
